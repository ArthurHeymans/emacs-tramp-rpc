#+TITLE: TRAMP-RPC
#+AUTHOR: Arthur Heymans <arthur@aheymans.xyz>
#+OPTIONS: toc:2

A native Rust RPC backend for Emacs TRAMP — faster remote file editing, Dired, Magit, Eglot, and terminals over SSH without shell parsing.

Traditional TRAMP (=tramp-sh=) runs remote file operations by sending shell commands over SSH, escaping paths, spawning external tools (=stat=, =ls=, =test=, =base64=), and regex-parsing their text output.  TRAMP-RPC replaces that with a ~850 KB static Rust server that Emacs auto-deploys on first connect and talks to over length-prefixed MessagePack-RPC.

* How It Works

- *No shell, no quoting, no regex parsing*: paths and file contents travel as raw binary MessagePack frames (non-UTF-8 filenames and binary files need no escaping or Base64).
- *Direct kernel syscalls*: ~stat~, ~read~, ~getdents~, and ~faccessat2~ run inside one persistent Tokio server instead of forking =/bin/sh= + coreutils on every call.
- *Multiplexed SSH*: reuses an SSH ControlMaster and honors =~/.ssh/config= aliases and =ProxyJump= directly.

* Why It's Fast

On real networks, round-trip latency dominates remote editing.  Opening a buffer, refreshing Dired, or running Magit can trigger dozens of sequential round-trips in shell-based TRAMP.  TRAMP-RPC collapses them:

#+HTML: <p align="center">
#+HTML:   <picture>
#+HTML:     <source media="(prefers-color-scheme: dark)" srcset="doc/assets/roundtrips-dark.svg">
#+HTML:     <source media="(prefers-color-scheme: light)" srcset="doc/assets/roundtrips-light.svg">
#+HTML:     <img alt="Round-trip collapse comparing sequential shell TRAMP against TRAMP-RPC batching, parallel prefetch, and push cache invalidation" src="doc/assets/roundtrips-light.svg" width="860">
#+HTML:   </picture>
#+HTML: </p>

- *Batched file ops (~batch~)*: packs up to 64 requests into a single round-trip executed concurrently on the server.
- *Parallel VC prefetch (~commands.run_parallel~)*: Magit and Majutsu batch read-only status/log queries into one round-trip, and ~ancestors.scan~ finds project/VC roots without walking parent directories one hop at a time.
- *Push-based cache invalidation (~fs.events~)*: remote =inotify= (Linux) and =kqueue= (macOS) watches push changes straight to Emacs, keeping metadata caches fresh with zero polling and powering ~file-notify~.

*Note on network RTT:* These medians were measured with =benchmark/benchmark.el= between two Linux hosts over LAN (~1.0 ms ping RTT, 9 iterations).  Actual wall-clock timings and speedups depend heavily on your real network RTT:

- Single-round-trip operations (~file-exists-p~, ~file-attributes~, ~file-read~) always have a floor of ~1 RTT, so relative speedups narrow slightly on high-latency links compared to LAN.
- Multi-round-trip operations (~connection-setup~, ~dir-locals-find-file~, ~locate-dominating-file~, batched ~file.stat~, Magit/Majutsu refreshes) eliminate many round-trips, so their wall-clock advantage grows *even larger* over WiFi, VPN, or WAN links.

* What Works Out of the Box

- Full TRAMP file handlers, Dired (~directory-files-and-attributes~ in one RPC), and optional zlib-compressed reads
- Magit, Majutsu, and Projectile remote optimizations
- Async processes (~make-process~, ~start-file-process~) and Eglot without shell wrappers
- Remote PTYs for terminal emulators (=vterm=, =eat=, =shell-mode=)
- Live filesystem watching (=inotify= / =kqueue=) with ~file-notify~ support
- Multi-hop routes including RPC-accelerated =sudo= (=/rpc:user@host|sudo:root@host:/path=)
- Automatic remote =PATH=, login shell, and =direnv= resolution

* Requirements

- Emacs 30.1 or later
- TRAMP 2.8.1.4 or later (install from GNU ELPA if your Emacs bundles an older version)
- =msgpack.el= 0.1.1 or later (from MELPA)
- SSH access to a remote Linux or macOS host

* Installation

** From Git (Emacs 30+)

#+begin_src elisp
(use-package tramp-rpc
  :after tramp
  :vc (:url "https://github.com/ArthurHeymans/emacs-tramp-rpc"
       :rev :newest
       :lisp-dir "lisp"))
#+end_src

** Doom Emacs

In =packages.el=:
#+begin_src emacs-lisp
(package! msgpack)
(package! tramp-rpc
  :recipe (:host github
           :repo "ArthurHeymans/emacs-tramp-rpc"
           :files ("lisp/*.el")))
#+end_src

In =config.el=:
#+begin_src emacs-lisp
(use-package! msgpack)
(use-package! tramp-rpc)
#+end_src

** Nix Flake

Add the flake input and overlay:
#+begin_src nix
inputs = {
  nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
  emacs-tramp-rpc.url = "github:ArthurHeymans/emacs-tramp-rpc";
};

# In your pkgs instantiation:
pkgs = import nixpkgs {
  inherit system;
  overlays = [ emacs-tramp-rpc.overlays.default ];
};
#+end_src

Then include =epkgs.tramp-rpc= in your Emacs packages (e.g. Home Manager's =programs.emacs.extraPackages=).  Server binaries for =x86_64-linux= and =aarch64-linux= are built automatically; override =archs= to target additional architectures (see [[file:doc/CONFIGURATION.org][Configuration]]).

* Usage

Open remote files with the =rpc= method:

#+begin_example
/rpc:user@host:/path/to/file
#+end_example

- Host aliases and =ProxyJump= entries in =~/.ssh/config= work directly without extra TRAMP hops.
- =/rpc:user@host|sudo:root@host:/path= starts the RPC server via =sudo= at full RPC speed.
- On first connect, release installs automatically download and deploy the ~850 KB server binary (Linux x86_64/aarch64/i686/ARM and macOS x86_64/aarch64).  When running from a git checkout without a cached binary, run ~M-x tramp-rpc-deploy-install-binary~ with a full TRAMP path (e.g. =/rpc:user@host:/=).
